Робочий процес

Зовнішня розробка уроків та експорт у Квант

Як автор і програміст обмінюються уроками: що йде на вхід, що генерується, як це потрапляє назад у платформу.

Технічний контрактВерсія 1.04 серпня 2026

Документ описує робочий контур, у якому уроки створюються поза кодовою базою Кванта (автор + AI-асистент), а потім імпортуються в платформу як звичайні дані. Кодова база Кванта при цьому не змінюється від уроку до уроку — змінюються лише записи в БД.

1. Ролі та межі відповідальності

Сторона Володіє Не робить
Квант (програміст) Граф знань, БД, API, редактор, плеєр уроків, статистика Не пише контент уроків вручну
Авторська студія (автор + AI) Педагогічний сценарій, тексти, приклади, ілюстрації, тести Не змінює граф знань

Головний інваріант, успадкований з 06. Уроки та варіанти:

Граф знань — джерело істини. Урок — лише представлення частини графа. Зовнішній контур створює представлення, а не структуру.

Тому експортований урок складається рівно з трьох типів записів, і всі вони вже існують у моделі даних:

NodeVariant   ← контент (пояснення, приклади, тести) прив'язаний до вузла графа
Lesson        ← назва та тип сценарію
LessonNode    ← порядок вузлів + вибір варіанта + опції показу

Жодної нової таблиці. Жодної міграції БД. Це навмисне обмеження: якщо для імпорту уроку потрібна міграція — контракт спроєктовано неправильно.

2. Цикл роботи

┌─ Квант ──────────────┐                        ┌─ Авторська студія ────────┐
│ 1. Експорт графа     │ ──── graph.json ────▶  │ 2. Вибір цільового вузла  │
│                      │                        │ 3. Замикання передумов    │
│                      │                        │ 4. Розкладка по етапах    │
│                      │                        │ 5. Генерація контенту     │
│                      │                        │ 6. HTML-прев'ю для правок │
│ 8. Імпорт (dry-run)  │ ◀── lesson.json ─────  │ 7. Експорт пакета уроку   │
│ 9. Імпорт + review   │                        │                           │
│ 10. Плеєр для учня   │                        │                           │
│ 11. Статистика       │ ──── feedback ──────▶  │ 12. Нові варіанти подачі  │
└──────────────────────┘                        └───────────────────────────┘

Кроки 2–7 — це те, що виконує AI-асистент разом з автором. Кроки 1 та 8–11 потребують роботи з боку Кванта, і саме вони описані нижче як технічне завдання.

3. Вхід: що Квант передає авторській студії

3.1 Формат

Один JSON-файл kvant-graph.v1.json на один предмет. Це знімок графа, не жива база.

{
  "schema_version": "1.0",
  "kind": "kvant.graph_export",
  "meta": {
    "subject_id": "subj-math-8",
    "subject_title": "Алгебра, 8 клас",
    "exported_at": "2026-08-04T09:12:00Z",
    "graph_version": "sha256:4f1c…"   // хеш вмісту; потрібен для контролю конфліктів
  },

  "nodes": [
    {
      "id": "nd-quadratic-equation",
      "title": "Квадратне рівняння",
      "node_type": "definition",
      "short_description": "Рівняння виду ax² + bx + c = 0, де a ≠ 0",
      "learning_outcome": ["Упізнає квадратне рівняння", "Виписує коефіцієнти зі знаками"],
      "typical_errors": ["Втрачає знак мінус у коефіцієнті b"],
      "tags": ["алгебра", "рівняння"],
      "difficulty": "base",
      "estimated_time": 8,
      "recommended_age": "13-14",
      "success_criteria": "Правильно визначає a, b, c у 8 з 10 рівнянь",
      "status": "approved"
    }
  ],

  "edges": [
    {
      "from_node_id": "nd-quadratic-equation",
      "to_node_id": "nd-discriminant",
      "relation": "prerequisite",     // prerequisite | next
      "type": "mandatory",            // mandatory | desirable | recommended | alternative | advanced
      "weight": 100,
      "min_mastery": 70,
      "priority": 1
    }
  ],

  "variants": [
    { "id": "var-…", "node_id": "nd-discriminant", "title": "Базове пояснення",
      "variant_type": "base", "status": "approved", "language": "uk" }
  ],

  "topics":  [ { "id": "top-…", "title": "Квадратні рівняння", "node_ids": ["nd-…"] } ],
  "lessons": [ { "id": "les-…", "title": "Дискримінант", "node_ids": ["nd-…"] } ]
}

3.2 Що обов'язкове, а що бажане

Секція Статус Навіщо
meta.subject_id, graph_version обов'язково прив'язка пакета та контроль конфліктів
nodes обов'язково без них урок нема на що спирати
edges обов'язково порядок етапів і визначення передумов
variants (без content) бажано щоб не плодити дублікати подачі
topics, lessons бажано щоб бачити, що вже покрито

Мінімум для старту: meta + nodes + edges. Решту можна додати пізніше без зміни контракту.

3.3 Спосіб доставки

Три варіанти, від найпростішого:

  1. Файл у репозиторії — data/graph/subj-math-8.json, оновлюється вручну. Достатньо для роботи вдвох.
  2. Ендпоінт експорту — GET /subjects/{subject_id}/export повертає той самий JSON. Реалізація тривіальна: наявні NodeRead + DependencyRead уже серіалізують усе потрібне.
  3. Read-only API-токен — асистент тягне граф сам через наявні /subjects/{id}/graph, /nodes/{id}/prerequisites, /nodes/{id}/next.

Рекомендація: почати з (1), додати (2) коли уроків стане більше десятка.

4. Що робить авторська студія

4.1 Алгоритм побудови уроку з графа

  1. Цільовий вузол — те, чого урок навчає (напр. nd-discriminant).
  2. Замикання передумов — рекурсивно збираються вузли з relation="prerequisite", type="mandatory". Вони стають матеріалом етапів «Вхід у тему» та «Ключові поняття». Глибина обмежується (зазвичай 1–2 рівні), інакше урок розростається до всього курсу.
  3. Топологічне сортування підграфа — дає базовий порядок проходження.
  4. Розкладка по ролях етапів — вузли розподіляються по педагогічних слотах (§5).
  5. Генерація контенту — для кожного вузла створюється NodeVariant з блоками, спираючись на short_description, learning_outcome, typical_errors, success_criteria з графа.
  6. Наступні кроки — вузли з relation="next" формують етап «Куди далі».

4.2 Чого асистент не робить

  • Не створює вузли графа. Якщо для уроку бракує поняття — воно йде в graph_suggestions як пропозиція, а рішення ухвалює викладач у редакторі.
  • Не редагує чужі варіанти. Створюються нові записи, старі не чіпаються.
  • Не вигадує node_id. Усі ідентифікатори вузлів беруться з експорту графа.

5. Ролі етапів (педагогічні слоти)

Макет плеєра задає фіксований набір ролей. Вони ж є критеріями блоку «Перевірка уроку».

Роль (block_role) Етап у плеєрі Обов'язковий Джерело з графа
intro Вхід у тему ✔ передумови + мотивуюча задача
goal Мета уроку learning_outcome цільового вузла
media Медіа / візуалізація ілюстрація до цільового вузла
concepts Ключові поняття вузли-передумови (definition)
explain Пояснення ✔ цільовий вузол (material)
example Розібраний приклад ✔ вузли типу algorithm / method
practice Перша спроба ✔ success_criteria
feedback Фідбек typical_errors
check Перевірка (тест) ✔ learning_outcome → питання
result Результат уроку обчислюється плеєром
summary Підсумок ✔ цільовий вузол, стисло
next Наступний крок ребра relation="next"

Шість обов'язкових ролей — це і є чек-лист «Перевірка уроку 6/6». Пакет, у якому бракує обов'язкової ролі, імпортується, але помічається попередженням.

6. Вихід: пакет уроку

6.1 Структура файлу

kvant-lesson-package.v1.json — самодостатній, імпортується однією операцією.

{
  "schema_version": "1.0",
  "kind": "kvant.lesson_package",

  "source_graph": {
    "subject_id": "subj-math-8",
    "graph_version": "sha256:4f1c…",   // проти якого знімка збиралося
    "exported_at": "2026-08-04T09:12:00Z"
  },

  "lesson": {
    "id": "les-discriminant-base",
    "title": "Квадратне рівняння: розв'язування через дискримінант",
    "lesson_type": "study",            // study | practice | review | assessment | summary
    "target_node_id": "nd-discriminant",
    "estimated_duration": 25,
    "author": "Андрій Верченко + AI",
    "language": "uk"
  },

  "variants": [
    {
      "id": "var-discriminant-base-explain",
      "node_id": "nd-discriminant",
      "title": "Звідки береться дискримінант",
      "variant_type": "base",
      "style": "проблемний",
      "audience": "8 клас",
      "difficulty": "base",
      "language": "uk",
      "status": "draft",
      "learning_objective": "Розуміє походження формули, а не лише запам'ятовує її",
      "estimated_duration": 6,
      "author": "AI (Claude), редакція автора",
      "version": "1.0",
      "content": {
        "format": "kvant.blocks/1",
        "blocks": [ /* див. §6.2 */ ]
      }
    }
  ],

  "lesson_nodes": [
    { "node_id": "nd-quadratic-equation", "variant_id": "var-…-intro",   "order": 0,
      "display_options": { "block_role": "intro",   "stage_title": "Вхід у тему" } },
    { "node_id": "nd-discriminant",       "variant_id": "var-…-explain", "order": 1,
      "display_options": { "block_role": "explain", "stage_title": "Звідки береться D" } }
  ],

  "graph_suggestions": [
    { "action": "create_node", "reason": "Урок спирається на поняття, якого немає в графі",
      "draft": { "title": "Виділення повного квадрата", "node_type": "method" } },
    { "action": "create_edge", "reason": "Логічний перехід після теми",
      "draft": { "from_node_id": "nd-discriminant", "to_node_id": "nd-vieta",
                 "relation": "next", "type": "recommended" } }
  ],

  "validation": {
    "roles_covered": ["intro","goal","media","concepts","explain","example",
                      "practice","feedback","check","summary","next"],
    "required_missing": [],
    "checklist": "6/6"
  }
}

6.2 Схема блоків контенту

NodeVariant.content — це JSON-поле, тож формат блоків визначаємо ми. Кожен блок має type, решта полів залежить від типу.

{ "type": "text",     "markdown": "Ти вже вмієш розв'язувати **ax + b = 0**…" }

{ "type": "formula",  "latex": "D = b^2 - 4ac", "display": true,
                      "caption": "Дискримінант" }

{ "type": "derivation", "steps": [
    { "latex": "ax^2 + bx + c = 0",              "note": "початкове рівняння" },
    { "latex": "x^2 + \\frac{b}{a}x + \\frac{c}{a} = 0", "note": "поділили на a" } ] }

{ "type": "callout",  "tone": "warning",        // info | success | warning | error
                      "title": "Найчастіша помилка",
                      "markdown": "Знак «мінус» належить коефіцієнту." }

{ "type": "terms",    "items": [
    { "term": "a", "definition": "старший коефіцієнт, не може бути нулем" } ] }

{ "type": "steps",    "items": [
    { "title": "Виписати коефіцієнти", "markdown": "a = 2, b = −5, c = −3" } ] }

{ "type": "table",    "headers": ["Знак D", "Коренів"],
                      "rows": [["D > 0", "два різні"], ["D = 0", "один"]] }

{ "type": "figure",   "render": "parabola",     // параметричний малюнок, без бінарників
                      "params": { "a": 1, "b": -1, "c": -6 },
                      "caption": "Два перетини з віссю" }

{ "type": "figure",   "render": "svg", "svg": "<svg …>", "caption": "…" }

{ "type": "input_task", "prompt_latex": "x^2 - 7x + 12 = 0",
                        "fields": [ { "key": "D",  "label": "D",  "answer": 1 },
                                    { "key": "x1", "label": "x₁", "answer": 4 },
                                    { "key": "x2", "label": "x₂", "answer": 3 } ],
                        "unordered": ["x1", "x2"],
                        "tolerance": 0.001,
                        "hint_wrong": "b² = (−7)² = 49, а 4ac = 48." }

{ "type": "quiz",     "question_markdown": "Скільки коренів має $3x^2-4x+5=0$?",
                      "options": ["Два", "Один", "Жодного", "Безліч"],
                      "answer_index": 2,
                      "explanation": "D = 16 − 60 = −44 < 0 → дійсних коренів немає." }

Правила:

  • Формули — завжди LaTeX, а не готовий HTML. Рендер — на боці Кванта (KaTeX уже підключено). Це гарантує однаковий вигляд у плеєрі, друку та мобільній версії.
  • Малюнки — параметричні (render: "parabola" + коефіцієнти) там, де це можливо. Плеєр малює їх сам, вони автоматично підхоплюють тему оформлення й не важать нічого. render: "svg" — запасний варіант для унікальних схем.
  • Жодних зовнішніх URL у контенті. Пакет має бути самодостатнім.
  • Невідомий type — плеєр пропускає блок і пише попередження в консоль, а не падає.

6.3 Ідентифікатори та ідемпотентність

id варіантів генеруються детерміновано:

variant_id = "var-" + uuid5(NAMESPACE_KVANT, lesson_id + "|" + node_id + "|" + block_role)

Наслідок: повторний імпорт того самого уроку оновлює ті самі записи, а не створює дублікати. Це робить імпорт безпечним для повторного запуску.

7. Що потрібно реалізувати в Кванті

Три частини. Перша — обов'язкова, друга — обов'язкова, третя — для зручності.

7.1 Імпорт пакета

Найпростіший робочий варіант — CLI, без нових ендпоінтів:

python -m app.import_lesson package.json --dry-run
python -m app.import_lesson package.json --mode upsert

Пізніше — ендпоінт POST /subjects/{subject_id}/import/lesson-package.

Порядок дій імпортера:

  1. Перевірити schema_version і kind.
  2. Перевірити, що source_graph.subject_id збігається з цільовим предметом.
  3. Порівняти graph_version з поточним. Розбіжність — попередження, не помилка: вивести перелік вузлів пакета, яких уже немає або які змінилися.
  4. Перевірити, що всі node_id існують і належать предмету. Відсутній вузол — помилка з іменем вузла (_set_nodes уже так робить).
  5. Upsert варіантів по id. Статус при імпорті завжди draft — навіть якщо в пакеті інше. Approve робить людина в редакторі.
  6. Створити або оновити Lesson.
  7. Замінити склад уроку — уже реалізовано в PUT /lessons/{id}/nodes.
  8. graph_suggestions — не застосовувати. Зберегти в окремий файл або таблицю пропозицій для розгляду викладачем.
  9. Вивести звіт:
Урок: Квадратне рівняння: розв'язування через дискримінант
  Варіанти:  створено 8, оновлено 3, без змін 1
  Склад:     12 вузлів
  Чек-лист:  6/6
  Пропозиції до графа: 2 (не застосовано)
  Попередження: вузол nd-vieta відсутній у графі — етап «Далі» показано без посилання

Гарантії, які дає імпортер:

  • ніколи не видаляє вузли, ребра чи чужі варіанти;
  • ніколи не змінює структуру графа;
  • при --dry-run не пише в БД взагалі.

7.2 Рендер блоків

У фронтенді потрібен один компонент-диспетчер:

BlockRenderer(block) → switch (block.type)
    text | formula | derivation | callout | terms | steps
    table | figure | input_task | quiz
    default → попередження в консоль, блок пропускається

Markdown + KaTeX уже підключені (комміт «Рендер контенту з формулами»), тож text, formula та derivation реалізуються майже без роботи. Інтерактивні блоки (input_task, quiz) потребують локального стану — відповідь, перевірка, пояснення.

7.3 Плеєр уроку

Сторінка /lessons/{id}/play, три колонки:

  • ліворуч — етапи уроку (з display_options.stage_title), клікабельні;
  • центр — блоки поточного етапу + навігація «Назад / Далі»;
  • праворуч — чек-лист ролей і панель AI-ментора.

Дані беруться так: GET /lessons/{id} → для кожного LessonNode підтягнути variant.content.blocks → згрупувати за display_options.block_role.

Референсна реалізація вже є — HTML-прототип уроку про дискримінант містить усю логіку навігації, рендер парабол, перевірку відповідей і підрахунок чек-листа. Його можна брати як специфікацію поведінки.

8. Роль HTML-прев'ю

Прев'ю — це не формат обміну. Джерело істини — JSON-пакет. Прев'ю потрібне для того, щоб автор побачив урок очима учня до імпорту й вніс правки, поки це дешево.

Прев'ю (HTML) Пакет (JSON)
Для кого людина програма
Живе посилання, одноразове у БД Кванта
Формули відрендерені LaTeX-джерело
Правки обговорення з автором результат правок

Прев'ю генерується з того самого пакета — отже, що бачить автор, те й потрапить у Квант.

9. Версіонування та конфлікти

Ситуація Поведінка
Граф змінився після експорту Імпорт проходить, у звіті — перелік розбіжностей
Вузол видалено з графа Помилка з іменем вузла; урок не імпортується частково
Варіант змінили в редакторі Кванта Upsert перезапише. Захист: --mode create-only
Повторний імпорт того самого пакета Ідемпотентний, дублікатів не буде
Потрібен відкат version у варіанті + збережений файл пакета

Рекомендація: зберігати пакети в репозиторії (data/lessons/*.json) — тоді історія уроків живе в git, а відкат зводиться до повторного імпорту старого файлу.

10. Що зробити першим

Крок Обсяг Дає
1. Експорт графа у JSON (файл або ендпоінт) ~1 год можливість будувати уроки з реального графа
2. CLI-імпортер пакета з --dry-run ~4 год уроки потрапляють у БД
3. BlockRenderer для 6 базових типів блоків ~4 год урок видно в інтерфейсі
4. Плеєр з лівою навігацією ~6 год учень проходить урок
5. Інтерактивні блоки (quiz, input_task) ~4 год практика й перевірка працюють
6. Ендпоінт імпорту замість CLI ~3 год імпорт з інтерфейсу редактора

Після кроків 1–2 контур уже замкнений: урок можна створити ззовні й покласти в базу. Кроки 3–5 роблять його видимим для учня.

11. Відкриті питання

  • Гранулярність варіантів. Один варіант на вузол чи один на роль етапу? Зараз у контракті — на роль (variant_id унікальний по lesson + node + block_role), бо це дає гнучкість. Але при цьому один вузол може мати багато варіантів того самого типу.
  • Спільні блоки. Чи можуть два уроки використовувати один варіант? Модель це дозволяє; імпортер має не перезаписувати варіант, що використовується іншим уроком.
  • Медіа-файли. Поки що контент самодостатній (LaTeX + параметричні фігури). Коли з'являться зображення й відео — знадобиться окремий розділ пакета з бінарниками.
  • Мова. language є в моделі, але маршрут «той самий урок іншою мовою» не спроєктовано.
